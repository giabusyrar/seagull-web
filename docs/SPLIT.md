# The Seagull split

The `Seagull` monorepo was split into three repositories on 2026-09-16.
History was **not** carried over — each repository starts from a single initial
commit. The original repository remains the record of everything before that
date, and still holds `GRAND_DESIGN.md`, `ARCHITECTURE.md` and
`docs/superpowers/`.

## Why it was cheap

There were **no Go imports across the three service groups**. Not one file in
`apps/gateway/**` imported `core-engine` or `reference-service`, and none of
them imported the gateway. Each service was already its own Go module with its
own Dockerfile and its own Railway service. The split moved directories and
repointed paths; it did not untangle code.

## Where everything went

| Was | Now |
|-----|-----|
| `apps/gateway/gateway-proxy/` | **Seagull-gateway** `apps/gateway-proxy/` |
| `apps/gateway/gateway-engine/` | **Seagull-gateway** `apps/gateway-engine/` |
| `apps/gateway/apisix-plugins/` | **Seagull-gateway** `apps/apisix-plugins/` |
| `deploy/apisix/`, `scripts/` | **Seagull-gateway** (same paths) |
| `packages/beauty-sdk/src/contracts/` | **Seagull-gateway** `packages/contracts/` (now a published npm package) |
| `apps/core-engine/` | **Seagull-core** `apps/core-engine/` |
| `apps/reference-service/` | **Seagull-core** `apps/services/reference/` |
| `apps/services/vision-ai-worker/` | **Seagull-core** `apps/vision-ai-worker/` |
| `apps/services/tryon-engine/` | **Seagull-core** `apps/tryon-engine/` |
| `apps/web/` | **Seagull-web** `apps/web/` |
| `packages/beauty-sdk/`, `packages/shared/` | **Seagull-web** (same paths) |
| `packages/goenv/` | **duplicated** into Seagull-gateway and Seagull-core |

One nesting level was removed on the way: `apps/gateway/gateway-proxy` became
`apps/gateway-proxy`, and `apps/services/vision-ai-worker` became
`apps/vision-ai-worker`. Every `go.mod` `replace`, Dockerfile `COPY` and npm
script was repointed to match.

## What changed beyond moving files

- **`packages/goenv` is duplicated, not shared.** It is one file with no
  external dependencies, and each repo keeps a `replace` to its own copy. If it
  ever grows, the two copies will drift and nothing will notice.
- **The contracts package changed shape.** `gen-contracts` still lives in
  gateway-engine, but now writes to `packages/contracts/` in the same repo,
  which is published as `@gateway-experience/contracts`. `beauty-sdk` imports
  that package instead of `../contracts`. Its `./contracts` subpath export and
  the matching tsup entry were removed.
- **Go module paths were left alone.** They are still
  `github.com/experience-gateway/...`, which has never resolved to anything —
  the modules are wired by `replace` and `go.work`. Renaming them would touch
  every import line and buy nothing while there are no cross-repo Go imports.
- **Backing services were consolidated.** Postgres, Redis and ClickHouse are
  defined once, in Seagull-gateway's `docker-compose.infra.yml`, on a shared
  `seagull` Docker network. Both service composes attach to it.

## What was deliberately dropped

| Dropped | Why |
|---------|-----|
| `packages/proto/` | Generated gRPC stubs with **zero importers** anywhere in the tree. |
| `prisma.config.ts` | Points at `packages/db/prisma/schema.prisma`, which does not exist. |
| `vercel.json` | Routes to `frontend/`, `backend/` and `gateway/` — directories that no longer exist. |
| `go.work.sum` | Regenerated by the Go toolchain on first build. |

If any of these is actually alive in a way the tree does not show, it is in the
original repository and can be restored.

## What the split did NOT separate

**The database.** `gateway-engine`, `core-engine` and `reference-service` all
run GORM `AutoMigrate` against the same `DATABASE_URL`. See
[SHARED-DATABASE.md](SHARED-DATABASE.md). This is the main thing the split made
worse, and it is worth fixing properly.

**Ports.** See [PORTS.md](PORTS.md).

**The contract release.** A change to a gateway-engine domain struct now needs
a publish in one repo and a dependency bump in another, with nothing enforcing
the order.

## Verification performed

Go is not installed on the machine where this split was prepared, so the Go
builds were verified through Docker instead — which also proves the rewritten
`COPY` paths. See the split report for exactly which builds were run and their
results.
